# Hash PayLink environment role inventory

Verified 156 live settings after removing AGENTIC_STREAMING_FROM_EMAIL (157 before this pass). This table includes identifiers, policy flags, amounts and storage namespaces, not just secret keys.

## Product findings

- Pocket bills is wired through PocketBillsPage, /api/pocket/bills, VTpass and Circle treasury/refunds. Parsed production-service configuration selects sandbox; canSandboxVend=true, canLiveVend=false, refundsReady=true. No live vending switch changed. Treasury wallet IDs/addresses and store namespace preserve payment/refund identity.
- AGENT_WALLET_SERVICE_SECRET authenticates service-wallet operations and governance fallback. ALLOWED_SERVICE_URLS is an outbound destination allowlist. MAX_SERVICE_AMOUNT and MAX_GATEWAY_DEPOSIT_AMOUNT cap spending. GATEWAY_BALANCE_CHAIN / DEPOSIT_CHAIN select Circle Gateway rails. DEFAULT_AGENT_SLUG / WALLET_ADDRESS identify the platform service wallet. These are payment infrastructure consumed by Pocket x402/connect/activate/marketplace and developer integrations, not the retired paid chat assistant.
- CIRCLE_CLI_ENABLED enables the pinned Circle CLI integration used by the service wallet backend; preserved.
- CDP_PAYMASTER_URL remains configured and referenced by /api/base-paymaster; VITE_BASE_PAYMASTER_URL points to that same-origin route. PaymentPage's external Base-wallet flow still calls tryBasePaymasterCall. This is distinct from Circle email-wallet Gas Station; removal would withdraw an existing optional sponsorship path. Provider policy/traffic validation and stronger proxy boundary review remain follow-up work; configuration is not evidence of recent usage.
- AGENTIC_STREAMING_FROM_EMAIL was only a lower-priority Polymarket alert sender fallback. Active ALERT_FROM_EMAIL shadows it, so removed the setting, source fallback and templates without changing the selected sender. The separate suspended agentic-streaming-report Render cron was not deleted; its own cron credential is outside this service and currently inactive.
- ZEROSCOUT_API_URL / INTEGRATION_SECRET remain used by Pocket guidance and shared intelligence. HASHWATCH_MEDIA settings belong to an unreachable retired media-helper branch; a dedicated removal of that shared provider branch and its obsolete tests remains, rather than deleting shared ZeroScout authentication.
- AGREEMENT_OPERATOR_ADDRESS and unsuffixed ARC_AGREEMENT_OPERATOR_WALLET*_IDEMPOTENCY_KEY have no exact reader in the reviewed source. Current agreement consumers use ARC_AGREEMENT_OPERATOR_ADDRESS and provisioning scripts use _MAINNET idempotency names. These old references remain pending deployment/provisioning reconciliation, not declared active merely because they exist.
- Developer portal keys, partner/API access, checkout signing, receipt signing/storage, agreement operator and webhook dependencies were preserved. No settings removed based only on an AGENT or BILLS prefix.
