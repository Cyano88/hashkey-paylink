# QR extension of online checkout

- QR web entry now supplies terminal options to the existing CheckoutChoice, CheckoutAssetChoice and BrowserCheckoutCard components. Stablecoins and Cash balance retain the online Pay on web / Pay with Pocket choice, email OTP, shared branding, verification, review and footer. The QR adapter supplies merchant, routes and editable amount; it does not introduce another payment UI.
- Public QR links use app.hashpaylink.com. Existing unified QR links on the Pocket host redirect to the app host. App handoff uses the existing /open/checkout/ Android link filter, with strict QR ID/method parsing and browser fallback.
- QR cash payouts require the same authenticated Base payment wallet used by online cash checkout. Basic KYC supplies the legal name server-side; client names cannot override it. A missing verified name blocks a new order. Existing-order reads remain available. Provider memo carries that name; receiving-bank sender display is not guaranteed by this code.
- All QR stablecoin routes, including existing Circle USDC receiving accounts, prepare the existing signed hosted checkout with a 15-minute expiry. Terminal revision, accepted route, receiving-wallet ownership, self-payment restriction, immutable attempts, shared allowance, receipts/history and reconciliation remain enforced.
- Cash QR preparation has a 15-minute deadline, capped by an earlier provider deadline. An expired unpaid intent cannot silently create another provider order. Submitted payment reconciliation remains separate from expiry. The reusable merchant QR does not expire.
- New regression covers shared method choice, mobile/desktop cash and stablecoin selection, app handoff parsing, inline email OTP, no payer-name field, no amount underline and no horizontal overflow. Existing online NGN checkout regression passed.
- Server regression covers signed USDC children on all six Circle networks, exact 15-minute lifetime, app-domain return URL and existing hosted USDT/X Layer/BNB safeguards. Payer regression rejects foreign wallets, missing Basic verification, and missing verified names. Provider-boundary regression checks memo, earlier provider expiry, session cap and expired-request rejection. Identity/provider/signing boundaries are mocked; no real payment or payout was performed.
- Main focused TypeScript diagnostics and source web build passed. Native dependency review retained the separate native footer through a re-export, added shared checkout helpers, and selectively aligned session restoration and explicit USDC/USDT payment handling without replacing native recovery functions. Native final build/device and deployment evidence follows after completion.
